## Design system *(shadcn/ui redesign)*
The web app is styled with Tailwind CSS v4 and shadcn/ui, initialised from preset `b1ZOMFeHQ` (style `base-maia`: Base UI primitives, Inter, lucide icons) on the existing Vite + React Router app — see TECHNICAL_DECISIONS.md TD-61. Generated primitives live in `web/src/components/ui/` and are edited only for real defects (e.g. `Button` is wrapped in `forwardRef` because this app runs React 18). Theme tokens live in `web/src/index.css`; on top of shadcn's own tokens, task/backlog statuses use seven `--tone-*` tokens (`lib/tone.ts`, `ToneBadge`, `Callout`) with light and dark values. Light/dark/system theme is a per-browser preference (`lib/theme.tsx`, stored in localStorage) toggled from the sidebar footer.

Layout: `AppShell` is a collapsible shadcn `Sidebar` (an off-canvas sheet below 768px), with page content capped at `max-w-7xl`. Shared building blocks: `PageHeader`, `Section` (titled card), `Callout` (tone-tinted outcome/warning), `ToneBadge`/`StatusBadge`, `Timeline` (task and backlog activity), `Dialog` + `DialogActions` (a controlled shadcn Dialog: mount to open, unmount to close). Form selects stay native (`NativeSelect`) so they remain plain `<select>` elements for accessibility and tests. Dense tables use the `.data-table` component class in `index.css`.

Projects and repositories (TD-62): "Create Project" asks only for a name and lands on Project Settings, whose Repositories section connects (`ConnectRepositoryDialog` — GitHub verification or local-git), edits and removes repositories, each with its own validation commands (`RepositoryCard`). The project header, cards and Overview show the one repository's URL/branch, or the names of several, or a "Connect a repository" prompt. `CreateTaskDialog` auto-selects a single repository and requires an explicit choice among several; task cards, task detail and backlog items name the repository when the project has more than one.

## CSV import and baseline *(Phase 4B.2)*
`AdjudicationPanel` gains a CSV-import section (paste or upload a human-filled template; a per-outcome summary is shown, never a fabricated success message) and a Baseline section (seed + three sizes, "Sample" freezes a versioned snapshot). A baseline with zero labels reads "NOT ESTABLISHED" and "Not measured" per category — never "0%" — and states the limitations attached to that exact snapshot.
